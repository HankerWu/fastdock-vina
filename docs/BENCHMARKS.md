# 基准结果与证据范围

前几节记录最初发布的 D 版本，分别量化相对上游及第一阶段优化 v1 的改进。后续工程改动各用对应的上一版本作为基线。

## 实验方法

| 项目 | 设置 |
| --- | --- |
| CPU | Intel Xeon Platinum 8362 |
| CPU affinity | 逻辑 CPU 16–19；共享服务器，未声明独占 |
| 工具链 | GCC 11.4、Boost 1.82 |
| 重复次数 | 每个案例、每个版本 3 次 |
| 执行方式 | 串行执行，轮换版本顺序，无预热 |
| 搜索设置 | 完整对接 `exhaustiveness=32`、`max_evals=0`，显式指定 `cpu=1` 或 `cpu=4`，固定随机种子 |
| 汇总方式 | 每个案例先取 3 次墙钟时间中位数；完整对接汇总为 19 个中位数之和 |

25 个案例的原始重复数据见 [`benchmark.csv`](../benchmarks/benchmark.csv)，执行记录见 [`runs.csv`](../benchmarks/runs.csv)，汇总见 [`summary.json`](../benchmarks/summary.json)。来源及文件对应关系见 [`source-manifest.json`](../benchmarks/source-manifest.json) 和 [PROVENANCE](PROVENANCE.md)。

这些结果描述上述固定环境；没有据此推断其他处理器、编译器、线程数或未测分子上的加速幅度。README 的 `exhaustiveness=8` 示例用于演示，参数与本节历史基准不同。

## 完整对接时间

| 版本 | 19 个案例中位数之和（秒） | 相对上游耗时降低 | 相对 v1 耗时降低 |
| --- | ---: | ---: | ---: |
| 上游基线 | 3242.524748 | — | — |
| v1 | 3074.107266 | 5.19% | — |
| 最终 D | 2989.230831 | 7.81% | 2.76% |

耗时降低按 `1 − 新版本耗时 / 参照版本耗时` 计算。以这些合计值计算，D 相对上游的加速比约为 1.085 倍；7.81% 是耗时降低比例，不是加速比增加比例。这里也未将逐案例加速比做几何平均。

![逐案例墙钟加速比](figures/wall-speedup.svg)

D 在 19/19 个完整对接案例上快于上游，在 18/19 个案例上快于 v1；`basic-ad4-dock` 相对 v1 约慢 0.36%。3 次重复有助于降低单次波动的影响，但不能替代更多重复或跨机器验证。

另有 6 个只评分／局部优化配置，单独统计，没有并入上述 19 项完整对接汇总。其中 `basic-vina-score`、`basic-vinardo-score`、`basic-ad4-score`、`basic-ad4-local` 相对 v1 略慢；所有原始值和回退项均保留在 CSV 与 `summary.json` 中。该共享服务器上的三次重复属于描述统计，未作统计显著性结论。

## 峰值内存

![逐案例峰值 RSS](figures/peak-rss.svg)

在 19 个完整对接案例上，D 的峰值 RSS 相对上游降低 28.71%–73.27%。这是包含 v1 已有查表共享、减少复制等修改的累计结果，不能全部归因于 D 的 BFGS 修改。

相对 v1，在全部 25 个案例上，D 的峰值 RSS 为 12 个更低、11 个更高、2 个相同，差值范围为 −0.21875 至 +0.265625 MiB。D 为 BFGS 使用完整对称矩阵和临时缓冲区，本身增加局部存储需求；这组小幅 RSS 变化不支持“D 持续降低内存”的结论。

## 等价性检查

| 检查 | 历史证据 |
| --- | --- |
| CLI | 225 次执行：PDBQT 逐字节一致，日志结果等价 |
| API | 75 次检查：十六进制 double 能量值、可获取的坐标完全一致 |

CLI 和 API 检查提供不同层次的证据：CLI 输出一致可验证实际文件结果；API 的十六进制 double 比较可检查打印舍入掩盖的差异。检查范围以记录中的输入和配置为限。

边界如下：

- 多配体、柔性受体和局部搜索场景的坐标 getter 覆盖不完整；“可获取的坐标一致”不代表已穷尽内部所有坐标。
- Python binding 和 `--write_maps` 未测试。
- 历史非有限值案例出现过 NaN 符号差异，不宣称所有 IEEE 浮点特殊值逐位一致。
- 已测案例的等价性不构成所有输入、平台、编译器或优化选项的普遍证明。

## 复测时保持的条件

复测应使用同一输入集、种子、搜索参数、CPU affinity 和线程数，并为各版本采用一致的工具链与编译参数。先检查输出等价性，再比较完整对接时间。请保留每次执行的原始时间、峰值 RSS、命令和输出，而不仅记录汇总百分比。

本仓库的构建脚本保留双精度与搜索逻辑，不启用 `fast-math` 等浮点数学改写。历史服务器测量与本仓库发布构建的实际验证应分别记录；历史结果不能自动视为在新机器上复现成功。

## 逐行复用受体候选

基线为 `70d97ef`。同一条 x 向网格行中，连续落入同一受体索引单元的点共享候选

按原来的轴顺序和受体原子顺序累加。无需为所有格点保留额外的受体索引或距离。
构建、验证、评分和读写共用同一套网格原子类型映射，普通碳和大环闭合碳只读写一次
对应的网格文件。

## 网格查表布局与局部搜索

基线为 `ea5ef5b`。该版本对 36 Å 盒的单次评分剖析中，约 95% 的 CPU 采样落在网格填充。
新版按受体类型和距离样本连续排列各配体类型的能量，只在建图期间保留这张表。
关闭精修时只对需要建图的类型对采样。显式精修保留更换配体或重载网格所需的类型范围。
分子内能量和显式受体能量从相邻的双精度样本取均值。BFGS 在每次局部优化开始时分配线性代数缓冲区，跨迭代复用，并移除了未被读取的能量历史。

两版均用 GCC 11.4、Boost 1.67 和相同发布参数构建。在共享 Xeon Platinum 8362 主机使用 1iep 受体，种子 42，默认 8 Å 截断。
单线程绑定 CPU 40，四线程绑定 CPU 40–43。每项交替先运行基线和候选。完整对接每版重复三次，其他场景每版九次。
限次搜索每条轨迹最多评估 650 次，保留 5 个搜索模式。批处理将随库已对接配体的四个 MODEL 分为四个输入，每个输入单线程、4 条轨迹。
完整对接使用默认评估预算和 9 个搜索模式。下表为中位数。[逐次墙钟、RSS、块 I/O 与输出摘要](../benchmarks/local-grid-lookup-bfgs.csv)

| 场景 | 墙钟时间，基线 → 新版 | 时间降低 | 峰值 RSS，基线 → 新版 |
| --- | ---: | ---: | ---: |
| 20 Å 建图和评分 | 0.198 → 0.182 s | 8.1% | 22.41 → 20.05 MiB |
| 36 Å 建图和评分，关闭精修 | 0.664 → 0.647 s | 2.6% | 52.82 → 44.82 MiB |
| 20 Å 对接，4 线程、8 条轨迹，限次 | 0.220 → 0.203 s | 7.9% | 24.54 → 21.67 MiB |
| 20 Å 对接，1 线程、32 条轨迹，限次 | 0.331 → 0.313 s | 5.6% | 22.93 → 20.08 MiB |
| 20 Å 批处理，4 个输入构象，限次 | 0.596 → 0.477 s | 20.0% | 42.35 → 40.15 MiB |
| 20 Å 完整对接，4 线程、8 条轨迹 | 19.701 → 19.385 s | 1.6% | 24.71 → 21.72 MiB |

完整对接三次的耗时范围有重叠，部分重复中新版稍慢。现有数据可见批处理的提速，完整搜索的耗时差异仍在单例波动范围内。
每个场景内，两版输出的长度和内容完全一致，块读写计数的中位数也相同。

另对 1iep 单线程、4 条轨迹、每条最多 20,000 次评估、5 个搜索模式的原生对接，在链接时用 GNU ld 的 `--wrap=_Znwm` 对 C++ 标量 `operator new` 计数。
基线请求 218,355 次、39,365,526 字节；新版请求 52,983 次、22,517,414 字节。两次的 PDBQT 逐字节一致。
这里统计进程累计申请量。表中的峰值 RSS 取自独立运行的常规二进制。

从 C++ 调用 Vina 和 Vinardo，在 21 × 23 × 25 Å 盒上检查五组配置，覆盖配体类型子集、全部网格类型、精修开关及 0.125、6.75、8、20 Å 截断。
直接比较全部 1,871,860 个格点的双精度值、未舍入评分及搜索得到的能量和坐标，均与基线逐位相同。
BFGS 另以 140 个小例覆盖不同自由度、零步、零梯度、回退和非有限值，检查最终构象、梯度、能量及评估次数。
原生 CLI 对照还覆盖柔性受体、大环、多配体、Vinardo 局部优化、自定义权重和未结合能、网格写入与重载、合成 AD4 网格，以及输入失败行为。


## 按需生成批处理网格

基线是 `f2ad517`。构建过程中按整段网格的最小距离筛除无法贡献能量的受体原子。
同一批次只为已加载配体和柔性残基需要的类型生成网格，按受体原子原有顺序累加，
各新增网格填充成功后再加入缓存。显式精修共用同一份受体索引和查表。
批次显式导出网格时仍生成全部类型。

两版使用相同的 GCC 11.4、Boost 1.67 和发布参数。在共享 Xeon Platinum 8362 上交替执行，
固定受体为 1iep 和种子为 42，默认截断 8 Å。普通单线程、短四线程、完整四线程和不同卤素
对照分别绑定 CPU 40、40–43、56–59 和 52。短对接每条轨迹最多评估 650 次，保留 5 个姿势。
20 Å 同配体批处理每构象 4 条轨迹，构象取自仓库的四个已保存 MODEL。完整对接保留 9 个
姿势，使用默认评估预算。普通场景每版 7 次，卤素场景每版 5 次，完整对接每版 3 次。
下表为中位数。[逐次墙钟、CPU、RSS、块 I/O 和输出摘要](../benchmarks/local-demand-driven-maps.csv)

| 场景 | 墙钟时间，基线 → 新版 | 时间变化 | 峰值 RSS，基线 → 新版 |
| --- | ---: | ---: | ---: |
| 20 Å 建图和评分 | 0.232 → 0.222 s | -4.6% | 19.48 → 19.54 MiB |
| 36 Å 建图和评分，关闭精修 | 0.760 → 0.702 s | -7.6% | 44.28 → 44.27 MiB |
| 20 Å 对接，单线程、8 条轨迹，限次 | 0.294 → 0.283 s | -4.0% | 19.77 → 19.64 MiB |
| 20 Å 对接，四线程、8 条轨迹，限次 | 0.208 → 0.198 s | -5.1% | 21.08 → 21.27 MiB |
| 20 Å 批处理，同一配体 4 个构象，限次 | 0.636 → 0.437 s | -31.2% | 39.64 → 19.82 MiB |
| 36 Å 批处理，同一配体 4 个构象，局部优化，关闭精修 | 1.537 → 0.711 s | -53.8% | 152.84 → 44.27 MiB |
| 20 Å 批处理，4 个不同卤素单原子输入，局部优化 | 0.327 → 0.477 s | +46.1% | 39.63 → 17.41 MiB |
| 20 Å 完整对接，四线程、8 条轨迹 | 20.414 → 21.144 s | +3.6% | 21.58 → 21.56 MiB |

36 Å 同配体批处理的 `gprof` 剖析中，基线约 95% 的采样落在网格填充，网格初始化从 20 张降到
5 张。四种卤素单独引入四种新类型，分次建图增加受体扫描，同时减少峰值内存。完整对接的
两组时间范围重叠，该测试未确认完整搜索有稳定提速。各场景的产物大小、内容和块 I/O 中位数一致。

原生 CLI 对照覆盖混合类型、同名输出、批次中跳过损坏文件、空批次、Vina/Vinardo、柔性残基、
多配体、网格导出和预计算网格重载、合成 AD4 网格以及 0.125、6.75、20 Å 截断覆盖。
逐项比较了退出状态、日志及 PDBQT 或网格文件。C++ 接口另在 16 种评分函数、截断和精修组合下
依次装载四个不同输入，比较标准评分、局部优化、搜索能量、坐标及重新装载受体后的多配体评分，
十六进制双精度输出完全相同。这些检查在一个受体及有限的补充输入上运行。
