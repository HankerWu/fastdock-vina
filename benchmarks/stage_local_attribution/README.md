# 首轮和入池前局优的独立干预

[事前方案](PROTOCOL.md)以已揭盲的三个病例定位因果路径。四种配置共享同一份 0bb827e 诊断构建、原始输入、种子、搜索预算和排序器。两位标记分别控制首次局优（hunt）和入池前局优（save）的主角度起始步。每格一核、三条轨迹，每条轨迹预算 12,000 次联合能量/梯度计算，使用原有的提议边界停机。一个提议可使末次计数超过预算。6 个角点发布的 PDBQT 全部复现历史 SHA-256。以稳定自由轨迹为来源，另起进程固定全部 4,410 个变异提议和 1,203 个满足二次局优调用条件的 hunt 返回。基线求解器在 5,613 个固定输入上逐项精确复现原能量、构象、笛卡尔坐标、调用和失败计数。两求解器每对的初始能量和方向导数完全相同。

## 自由轨迹

每格报告发布首姿 / 池最优，单位 Å。RMSD 在接收受体坐标系，按原有口袋 Cα 对齐和化学对称映射计算。

| 原候选的病例类型 | 均关闭 00 | 只开 hunt 10 | 只开 save 01 | 两者均开 11 |
|---|---:|---:|---:|---:|
| 改善，DYRK1A 7AKL→3ANR，85237 | 13.457 / 12.365 | 0.771 / 0.771 | 12.553 / 12.553 | 1.537 / 1.537 |
| 恶化，EPAS1 5TBM→4GHI，85231 | 0.671 / 0.671 | 3.943 / 3.052 | 0.678 / 0.678 | 14.297 / 3.049 |
| 近持平，FKBP1A 1FKH→1FKG，85237 | 6.786 / 4.615 | 5.686 / 4.025 | 7.055 / 6.095 | 6.785 / 6.785 |

- DYRK1A 从 00 换成 10 后，提议从 1,762 降至 1,338；≤2 Å 的 hunt 从 0 次增至 10 次，其中 9 次被接受，1 次在 save 后仍接近并进入最终发布池。将稳定的 1,762 个提议交给限幅求解器，最优 hunt 从 11.015 降至 8.266 Å，仍无一进入 2 Å。自由路径上的后续提议是该改善的必要部分。
- EPAS1 的 00/10/01/11 各有 202/0/227/0 次 ≤2 Å 的 hunt。稳定源态上单独改 hunt 求解却得到 204 次近姿。更换自由路径改变了进入的盆地。10 与 11 的池最优仅差 0.003 Å，首位相差 10.354 Å，表明预存储局优在 hunt 条件改变后大幅增加了发布排序损失。首姿的有限差分交互量 11−10−01+00 为 +10.347 Å，同一条轨迹内不能将此数值再唯一分解到接受、保存与打分。
- FKBP1A 的 00 与 11 首位仅差 −0.00087 Å，池最优却恶化 2.170 Å。10 中唯一一次 ≤2 Å 的 hunt 被接受，save 返回中无近姿。三种病例说明仅用终点首位会遗漏不同的候选池和选择损失。
- 三格共九对轨迹中，单开 hunt 的第一个状态差异全部出现在第零次 hunt 返回。单开 save 的首个差异全部出现在二次局优返回，六对在第零次，另外三对分别在第 10、22、53 次。差异出现时对应 source 和变异提议逐位相等。

## 同源求解与实际成本

| 稳定路径上的阶段 | 输入数 | 联合调用 00→11 | 十次回溯耗尽 00→11 | 触发平移缩短的求解数 | 被缩短的方向数 | 求解器内 CPU，秒 00→11 |
|---|---:|---:|---:|---:|---:|---:|
| hunt | 4,410 | 91,421→110,974 | 3,301→1,916 | 3,987 | 4,781 | 0.30845→0.33116 |
| save | 1,203 | 16,753→25,088 | 1,114→980 | 1,099 | 1,274 | 0.04496→0.06255 |

旧限幅将完整切向量乘以同一个因子。在已经触发限幅的方向上，记录首试前后平移范数之和，hunt 由 6.604×10⁹ Å 降至 6,247.49 Å，save 由 8.563×10⁸ Å 降至 1,913.54 Å。这些量累加了每一步近似逆 Hessian 和梯度给出的**试探**平移，包含随后遭到拒绝的方向。原始极值可远大于口袋尺度，实际移动量由线搜索接受决定。这项观测支持尝试登记的平移保留方向，单独不能证明平移缩短造成了某一释放姿势的误差。

12 次自由轨迹运行的 CPU、逐启动墙钟之和与单进程峰值分别为 4.270 s、4.432 s、60,432 KiB。6 次固定源态启动合计 2.040 s、2.096 s、63,940 KiB。这些成本包括读入、建图、运行与诊断 I/O；求解器内计时使用线程 CPU 时钟，只包围真实局优调用，含数值观测开销，计时分辨率及调度会影响短耗时。本轮复用历史制备输入。结构面板记录了其制备成本。第一次构建观察器时文字替换的匹配条件失败，修正观测脚本后从原提交完整重建；失败发生在编译和对接之前。

归档保留每个 S/P/H/A/D/M/I/O/F 事件、实际发布坐标、日志、输入构象、固定求解结果与运行收据。事件定义沿用 [BFGS replay](../bfgs_source_replay/README.md)。H/D 的最后四列为触发非零平移缩短的方向数、这些方向在限幅前后的平移范数之和（Å）、此次求解的线程 CPU 纳秒。I/O/F 仅用来追踪合并、精修和排名，额外的 BFGS 诊断字段只在 H/D 有意义。独立读取器以 SVD 重算口袋对齐、直接读 PDBQT 坐标和原始事件，核对 108 个发布姿势、36 条路径、11,226 个锁定返回、5,613 个同求解器返回及六个角点。全部表格还在新目录解包后逐字节复现。

从仓库根目录复现，环境沿用四版结构面板，Boost 1.83，GCC 14.2。以下路径均需为新目录。

```sh
export OPENBLAS_NUM_THREADS=1
D=benchmarks/stage_local_attribution
python "$D/pack.py" restore "$D/raw" /tmp/stage-offline
python "$D/analyze_stages.py" /tmp/stage-offline /tmp/stage-tables
diff -qr "$D/results" /tmp/stage-tables
python "$D/verify_stage.py" /tmp/stage-offline /tmp/stage-tables
bash "$D/build.sh" /tmp/stage-src "$BOOST_PREFIX"
python "$D/run_stages.py" /tmp/stage-live /tmp/stage-src/build/vina
python "$D/analyze_stages.py" /tmp/stage-live /tmp/stage-live-tables
```

重新运行后，实际时钟和包含时钟字段的原始日志哈希随执行而变。脚本在动态运行中核对发布池、归档角点、稳定源态和同求解器返回的所有非计时字段。
