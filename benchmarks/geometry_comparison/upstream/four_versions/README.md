# 四个固定源码版本的结构预测与计算成本

这里复用 `geometry_comparison/upstream` 已存在的两个冻结面板。40 个 12k 配对格中，官方 Vina 和真实分叉前父版的首姿 RMSD 全部一致。相同输入和评估上限下，当前 Pro 的交叉对接平均首姿误差从 2.863 升至 6.016 Å，同晶从 6.794 升至 7.175 Å。分阶段重建两个历史优化器版本，在这两个已查看面板上定位了很大一部分差异。本轮修复固定评分接口和输出坐标域，独立重跑末版后，40 个固定预算首姿误差与轮前稳定 Pro 完全相同。

## 版本、覆盖与读数

| 角色 | 真实源码 | 来源与实际行为 |
|---|---|---|
| 官方 | `forlilab/AutoDock-Vina@8eb40404` | 上游 `v1.2.7` 标签的未修改 C++ 源，使用相同编译器和优化选项重建 |
| 父级 FastDock | `HankerWu/fastdock-vina@05ec6ed5` | 首次 Pro 源码变更 `5f3fc4b` 的唯一父提交，使用自己的建图、搜索和评分代码 |
| 轮前稳定 Pro | `f46aa377` | 原生势、原生选姿及原生精修；额外打开被动计数 |
| 本轮末版 Pro | `5847b1bc` | 新增固定输入验证、批量评分输出与原生刚性精修的可发布坐标域检查 |

前三个 FastDock 系列源码版本可打印相同的历史版本标签。完整源码 Git tree、SHA、编译器、Boost 动态库和独立生成的二进制哈希收录于 [builds.json](builds.json)。四臂默认 Vina 势、网格间距 0.375 Å、显式末端精修；默认搜索深度 8、启发式评估数、最多 9 个模式、输出能窗 3 kcal/mol。Pro 新方法保持其版本实际默认设置。默认小组统一一核、已知口袋及随机种子；其余参数采用各程序默认值。固定上限组统一每轨迹 12,000 次、三条轨迹、九个模式、能窗 100 kcal/mol、24 Å 已知口袋。昂贵的真实比较仍独立执行每一臂。

同晶组的十个复合物分属 PHIP、BPTF、HSP90AA1、BCL2L1、BAZ2A、BRDT、BCL6、USP5。交叉对接组为 EPAS1、FKBP1A、RBP4、FABP4、DYRK1A 各两座晶体的双向查询。两组固定上限均用两个历史种子。分层内以下均值以每个运行格等权；同晶 BPTF 与 BCL6 因有两座晶体，各占其余靶点两倍权重。各靶点、每个完整运行和全部排名另存，可按不同权重重算。面板中有新旧不同骨架及接收受体，长期可比较性来自沿用同一制备、盒子、输入和评估映射。它们在以往研发中用过。全局搜索从冻存的图生成配体起步，晶体坐标只参与接收口袋定义和事后受体坐标系内 RMSD 的计算。

交叉 12k 相对官方及父版有 4 格改善、16 格退化。池内最佳均值从 2.482 升至 4.925 Å，排序损失从 0.380 升至 1.091 Å。首姿 P95 从 5.867 升至 14.504 Å，超过 5 Å 由 5 增至 11 格。同晶有 10 格改善、10 格退化，P95 从 9.093 升至 11.334 Å，超过 5 Å 的格数却从 19 降至 17。完整成本标定组对官方均值只差 +0.037 Å，中位数改善，P95 从 10.289 升至 13.941 Å。对使用同一较深上限的父版，此组均值退化 2.210 Å；这一组与 12k 面板采用相同受体、不同种子及不同 FastDock 评估上限，两行相减混有种子差异。

末版与稳定版相比，54/65 个完整发布文件字节一致；65 格中 64 个 Top-1 RMSD 一致。唯一改变量为 CPU 标定的 5TBM→4GHI、种子 93563，从 15.238101 降至 15.238021 Å。改变量小于 PDBQT 的 0.001 Å 坐标记录精度。部分更低排名的姿势随打印坐标域校正而变化。中间候选 `673f226` 独立执行的全部 65 个文件与稳定版逐字节一致。[中间候选的运行与原始发布](intermediate/)

主试验固定 180 秒墙钟和 2 GiB 地址空间。官方默认 1FKG→1FKH 达到墙钟上限（143.646 CPU 秒、180.083 墙钟秒），无输出。其余三臂与其余官方运行全部有输出。主表始终保留 259/260 与该次失败；默认组按四个共同成功格比较，末版相对官方首姿平均变化 −0.548 Å。按登记另给该官方病例 900 秒上限，以相同种子和输入重跑，118.582 秒墙钟内完成（112.868 CPU 秒），首姿 1.458455 Å。用补跑补全五格后，末版相对官方平均变化为 +0.402 Å，3 格改善、2 格退化。是否完成改变了可比分母和效应方向。[首轮失败记录](results/cells.csv) · [补跑、合并五格与验证](default_completion/)

## 两次真实 BFGS 变更对应的差异

追加检验在看到父版与稳定版差异后登记。重建 `e7031e9`（接受点修复之前）及 `2326430`（回溯失败保留最后接受点）。从 `e7031e9` 到 `2326430`，再到 `6c251f5`，`src` 差异均仅为 `src/lib/bfgs.h`。`6c251f5` 与轮前稳定版的整个 `src` tree 相同。各历史版本用完整源码构建；两个追加版本的 80 次运行共发布 714 个姿势，均从坐标独立复算。下表是新版本减前一版的配对均值，负数表示误差降低。

| 前一版 → 后一版 | 双向交叉 Δ首姿 / Δ池最低 / Δ排序损失 Å | 首姿改善 / 持平 / 退化 | 同晶 Δ首姿 / Δ池最低 / Δ排序损失 Å |
|---|---:|---:|---:|
| 真实父版 → e7031e9 | −0.058 / +0.0004 / −0.058 | 4 / 16 / 0 | −0.029 / −0.046 / +0.017 |
| e7031e9 → 2326430 | +2.958 / +2.172 / +0.786 | 4 / 0 / 16 | +0.381 / +0.163 / +0.219 |
| 2326430 → 轮前稳定 | +0.252 / +0.270 / −0.018 | 5 / 11 / 4 | +0.028 / +0.440 / −0.412 |

交叉组中，首次保留接受点的修复使每格 hunt 调用均值从 691.50 增至 1431.05，三阶段合计评估却从 36521.5 减至 36289.6。较短的局部调用把固定评估上限分摊给了更多 Monte Carlo 提议。RBP4 的首姿平均增加 5.755 Å，其中池最低增加 5.630 Å；EPAS1 的首姿平均增加 3.292 Å，其中排序损失增加 1.957 Å。FKBP1A 的首姿反而平均降低 0.190 Å。历史单头文件改动因果改变了该完整搜索程序的输出；早停、提议个数、随机轨迹与随后排名各自的独立贡献仍需对照。数值正确性、局优质量和全局预测表现是三个不同实验终点。[事前追加登记](BFGS_PROTOCOL.md) · [全部病例、计数、阶段差值及复算](bfgs_results/)

## 成本和重建

| 四臂主试验 CPU 秒 | 官方 | 父版 | 稳定 | 末版 |
|---|---:|---:|---:|---:|
| 同晶 12k | 36.03 | 15.66 | 8.86 | 8.55 |
| 双向交叉 12k | 41.96 | 16.87 | 8.96 | 7.74 |
| 交叉历史 CPU 标定 | 39.48 | 47.12 | 38.47 | 33.64 |
| 五格默认，含失败消耗 | 366.83 | 245.47 | 129.57 | 109.85 |

交叉成本标定沿用先前另用种子 74317、只读计时数据定出的每个复合物上限。末版 / 官方的实测单格 CPU 成本比中位 0.923，范围 0.299–1.836。本机多进程共同运行，墙钟、调度及 CPU 频率随任务变化。最终与稳定搜索计数匹配且两次测量负载有别，单次计时差异不足以估计本轮代码的加速比。不同引擎的常用 Vina 评估是一次能量和梯度联合计算；相同上限不等于相同提议数、墙钟或浮点工作。官方和父版没有原生计数参数，另在十个固定交叉格各用相同源码加只读计数运行，20/20 与其未修改程序输出逐字节一致。两臂在这十格各实耗 hunt 272272、二次局优 88791、显式精修 4090 次。其余官方和父版格这些计数保留为空。Vina 启动、输入读取、建图、搜索、精修、打分、输出的单次进程用户 / 系统 CPU、墙钟与峰值 RSS 逐格保留；未把合计冒充为各阶段独立用时。[计数追加登记](COUNTERS.md) · [计数与逐例哈希](counter_results/)

全部固定面板合计 260 次主执行，1155.065 CPU 秒、1442.036 逐作业墙钟秒之和；主输出含 2276 个带序姿势，两种独立的对齐和 PDBQT 解析所得最大 RMSD 差为 8.9×10⁻¹⁵ Å。额外研究开销为中间候选 192.291 CPU 秒、两次历史 BFGS 分叉合计 36.810 CPU 秒、遥测复跑 29.587 CPU 秒和官方默认补跑 112.868 CPU 秒。并行作业的墙钟相加不等于整场实验历时。历史已制备输入由四臂复用；其原始离线制作时间未归档到此表。计时不含编译、数据下载和事后几何统计。另从归档的 PDB/CCD 实际重建十个交叉组配体和十个受体，20/20 个 PDBQT 与冻存输入按 SHA-256 完全一致。逐结构制作合计 22.817 CPU 秒（配体图、构象与参考映射 1.083，受体 21.541，其余解析约 0.194）；逐结构墙钟之和 22.904 秒。受体/配体被种子、版本与三个交叉组预算复用一次。此独立重建只覆盖交叉组；同晶组的历史制备 CPU 未测。[逐结构制备时间与哈希](preparation.json)

## 复现入口

从仓库根目录运行，构建需要 GCC/Clang 与 Boost，质量统计需要 Python、NumPy、SciPy、pandas。工作目录使用新的空路径。默认 CPU 实验使用 Linux 的 `wait4`、`RLIMIT_AS` 与以 KiB 为单位的 `ru_maxrss`。

```bash
D=benchmarks/geometry_comparison/upstream/four_versions
bash "$D/build.sh" /tmp/vina-four-builds /path/to/boost-prefix
for a in official parent stable candidate; do
  OPENBLAS_NUM_THREADS=1 python "$D/run_panel.py" "$a" "/tmp/vina-four-builds/$a/vina" "/tmp/vina-four-runs/$a" --jobs 2
done
python "$D/evaluate.py" /tmp/vina-four-results --collect /tmp/vina-four-runs
# 从仓库根目录只读复算所有已归档姿势、主要汇总、补跑和计数，无需编译或联网。
OPENBLAS_NUM_THREADS=1 python "$D/offline.py"
# 如需单独重建交叉组制备时间，另安装 RDKit、Meeko、Gemmi、OpenMM、PDBFixer。
OPENBLAS_NUM_THREADS=1 OPENMM_CPU_THREADS=1 python "$D/preparation.py" /tmp/vina-prep /tmp/prep-timing.json --jobs 2
```

`bfgs.py run` 对每个精确历史版本执行两组 12k 面板，`bfgs.py analyze --core-archived` 可配合已归档的 `results` 验证中间版本和两次连续改动。`counters.py run` 使用 `benchmarks/cumulative/affinity/instrument.py` 对相符源码添加只读计数后的二进制；`counters.py verify` 只在与原始池字节相同的情况下登记计数。`completion.py retry` 和 `archive` 保存单独的默认补跑，可用 `combine` 核对覆盖所有主试验默认超时格。
