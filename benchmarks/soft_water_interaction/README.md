# 半软受体搜索与可移动结晶水重排能否相互补足

在人 BRD9 的一个交叉方向，软排斥搜索把 0.833 Å 的姿势带入候选池，结晶水重排随后把它选为首位。反向对接时，同一策略选出了距实验位置 10.837 Å 的姿势。在四个迁移靶点的 48 个条件中，组合使平均首姿误差比基线增加 0.566 Å。现有证据支持保留该病例作机制研究，默认算法保持现状。[事前协议](PROTOCOL.md) · [逐条件四臂配对表](results/pairs.csv)

## 两个机制实际作用在哪里

A 沿用已有的刚性受体 Late 搜索。四条轨迹中的两条将受体网格的排斥系数减半，所有候选都用完整干势显式精修。B 使用接收受体中按同一几何规则识别的水，每个位点在以实验 B 因子给出的空间分布上做 11³ 点积分。对每个已发布姿势，加入占据模型的置换代价，按升序重排。接收受体的结晶水引入了相对于干模型的额外实验信息。重排前后的池、坐标、候选数量及已有搜索次数完全相同。查询配体晶体坐标只用于 RMSD 评估和事后解释。半软搜索和水位点模型分别沿用原实现，没有新拟合的权重。[搜索实现及研究依据](../paired_crossdocking/README.md) · [水占位模型及原始对照](../mobile_water/README.md)

历史面板用三个已测人蛋白的 30 个双向交叉对接条件重放，覆盖 599 个姿势。两组搜索的原生池此前已生成；加入 B 的原生组也已有历史对照。本轮补齐软搜索加 B 的组合，并从坐标复算全部四臂。迁移面板用 BACE1、BRD9、CHEK1、EPHX2 的八个受体重新对接。每个双向条件在 3,000 和 12,000 轨迹上限使用三个相同种子，合计 96 次搜索、958 个姿势，其中 48 对可逐条件比较。96 次全部成功。所用靶点此前参与过独立的扭转研究，四臂组合的分析在运行前已冻结。两批没有共同靶点。RMSD 为全配体重原子在受体口袋坐标系中、以预先冻结的等价映射计算的误差。对另一配体共晶受体的参考来自跨受体对齐，真实查询姿势在该受体中仍可能变化。[迁移输入、受体对齐、PDB 来源和化学制备](../torsion_proposals/README.md)

定义配对交互量 I=R11−R10−R01+R00，其中 Rij 是四臂首姿误差。历史面板平均 I=−0.185 Å，组合相对基线 +0.361 Å（4 改善、13 退化、13 相同）；迁移面板 I=−0.154 Å，组合相对基线 +0.566 Å（18 改善、21 退化、9 相同）。两批的配对差中位数都为零。迁移组水重排作用于常规搜索时增加 0.151 Å，作用于软搜索时约减少 0.003 Å，两种小效应之差可以产生负交互。逐条件严格优于另外三臂的仅有 2/30 和 3/48。迁移组按靶点重采样，组合减基线的均值描述性 95% 区间为 [−0.427,+1.671] Å，交互区间为 [−0.950,+0.467] Å。这里只有四个靶点，精度有限。按枚举 4⁴ 组重采样保留每个靶点内所有相关结构、种子和预算。历史面板相应只含三个靶点。[配对差的完整分布](results/contrasts.csv) · [按靶点重采样](results/target_bootstrap.csv)

迁移组中，A+B 相对基线在 BACE1、BRD9、CHEK1、EPHX2 的均值差分别为 +2.110、+0.557、−0.755、+0.354 Å。对应 I 为 −1.281、+0.622、+0.041、0.000 Å。BACE1 一例 2ZJM→2B8L、43117、12,000 档的四臂结果依次为 3.885、13.131、11.748、3.885 Å。联合机制恢复了起始表现，I 却达 −17.109 Å，单这一例就足以改变整体交互均值的符号。EPHX2 的两个受体虽有 21 和 13 个合格水位点，任一搜索池中加水均未改变首位。CHEK1 的 2YWP 没有合格位点，仍完整纳入。

两组搜索只在历史、迁移各一个条件存在发布数差异。把两池同时按原排名截至较小数量（各为 9 和 8）后，这两格四臂的首姿误差和池内最小 RMSD 全部保持一致。原生池、软池内水引起的首位索引变化在历史组各 5/30 次，在迁移组为 15/48、17/48 次。每个变更首位的水位点分项均存档。[逐姿分项与候选数](results/poses.csv) · [逐位点反事实](results/changed_winner_sites.csv)

## 相同水模型如何在 BRD9 的正反方向改变排序

6YQW 的配体进入 6Y7L，种子 43103、3,000 档时，四臂依次为 2.560、2.560、4.118、0.833 Å。新盆地来自 A 的发布池，其 0.833 Å 姿势按干分排第二，仅比首位落后 0.061。加水后该候选的总罚分 0.049，原首位为 1.185，成功换首。水 A406 和 A437 分别贡献 0.720 和 0.416 的相对优势。接收坐标系中的查询晶体参考在这两个位点的罚分为 0.041 和接近零。原生池的最好姿势是 2.560 Å；只对其重排无法恢复这个 0.833 Å 候选。同种子 12,000 档也选中 0.833 Å。两个预算存在共享结构和种子。[6Y7L 实验结构](https://www.rcsb.org/structure/6Y7L) · [6YQW 实验结构](https://www.rcsb.org/structure/6YQW)

反向把 6Y7L 配体放入 6YQW，43103、12,000 档的四臂依次为 7.081、6.794、7.081、10.837 Å。软池的第六名比第一名干分落后 0.192，但总水罚分仅 0.013，原第一名则为 0.703。避开 A377 就获得了 0.478 的相对优势，足以逆转干分。新姿势与参考的误差反而增大。这表明仅按位点排斥可以奖励同时避开水和真实结合位置的姿势。实验未测这些水的置换自由能或动态占有率。软搜索降低迁移组的平均池内最小误差，识别其中好姿势的能力仍有限。[全部改变首位的局部分项](results/changed_winner_sites.csv)

## 成本和复现

转移组每个预算与搜索方法各有 24 次单 CPU 搜索，用两个并发进程运行。3,000 档原生与软搜索的逐任务墙钟合计为 5.36、8.47 秒；12,000 档为 7.79、11.02 秒。对应 CPU 合计为 5.30、8.38、7.75、10.98 秒。软搜索需要额外网格。在此主机上，12,000 档原生的用时接近且略低于 3,000 档软搜索，在完全相同的 24 个条件上，前者平均首姿 5.913 Å，后者叠加水后 7.307 Å。每个条件是一次测时。958 个迁移姿势的水能量求值合计 1.84 秒，受体位点准备约 0.14 秒，此数不含输入读盘、RMSD 和统计。运行未调用 GPU 或自由能计算。该结构面板没有同测定 Ki/Kd 数据。[逐次时间和资源](results/transfer_cost.csv) · [各阶段求值数](results/counters.csv) · [重排时间](results/scoring_cost.csv)

从仓库根目录，以 Python、NumPy、SciPy、pandas、RDKit、Gemmi 和 Meeko 运行以下命令。源代码树和运行的二进制摘要可在校验记录中查到。新的 PDBQT 和控制台日志保存在 176 KiB 压缩包中；评估脚本由坐标重新读取每个模型、重新叠合蛋白并计算所有受体水位点。历史臂逐个核对了 599 个 RMSD、300 个既有加水后分数。

```bash
D=benchmarks/soft_water_interaction
W=$(mktemp -d)
mkdir -p "$W/historical" "$W/transfer"
for a in fixtures poses-3000 poses-12000; do
    tar xf "benchmarks/paired_crossdocking/$a.tar.xz" -C "$W/historical"
done
tar xf benchmarks/torsion_proposals/fixtures/inputs.tar.xz -C "$W/transfer"
tar xf "$D/transfer_outputs.tar.xz" -C "$W/transfer"
# 如需从头对接，可在运行下面的评估之前执行此行，VINA 为本分支编译的可执行文件。
# python "$D/transfer.py" "$VINA" "$W/transfer" --jobs 2
export OPENBLAS_NUM_THREADS=1
python "$D/evaluate.py" "$W/historical" "$W/transfer" "$W/results"
python "$D/localize.py" "$W/historical" "$W/transfer" "$W/results"
cmp "$D/results/poses.csv" "$W/results/poses.csv"
cmp "$D/results/pairs.csv" "$W/results/pairs.csv"
cmp "$D/results/changed_winner_sites.csv" "$W/results/changed_winner_sites.csv"
```

两次独立启动的 96 次迁移搜索输出逐字节相同；相同代码重复运行用于检验复现性。重新汇总也逐字节复现了确定性表格。[复跑校验](results/verification.json) · [输出结构与日志](transfer_outputs.tar.xz)
