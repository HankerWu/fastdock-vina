# 补环改变候选池，还是改变已有候选的排序？

在 Aurora A 的 2X6E 上，补环后有一部分已发布姿势的直接分数改变，但更换受体没有改变任何一个固定池的赢家。反过来，把新原子连同其原子类型与文件顺序全部保留，仅平移到盒外，八个盲搜输出与缺段受体逐字节相同。两个对照共同把这组首姿变化定位到发布候选的产生或保留阶段。它们无法进一步判断某条轨迹的哪一步首次发生分歧。[测量前方案](../POOL_PROTOCOL.md) · [受体准备与盲搜](../README.md)

## 全部发布坐标的四受体交叉评分

两种配体、四枚种子及四种受体产生 32 个来源池、285 个发布模式。对每份输入配体保留原盲搜使用的推断键图，坐标从保存的 PDBQT 逐个导入同一生产实现。每个受体用相同盒、同一未结合参考零点，计算完整精度的显式受体分 $S(X)=a_L(E_\mathrm{inter}(X)+E_\mathrm{intra}(X))$，单位为 Vina 名义分数。`a_L` 是原配体的转子归一化斜率。AT9283 这一路径继承默认推断图；前序已知化学图的十个中心另有专门对照。本试验不混用两种图的数值。

原 2,421 个受体原子记录保持字节一致，三个模型各追加相同类型和数量的 134 条记录，含 101 个重原子。设 $\delta_i=S_{\rm loop}(X_i)-S_{\rm dry}(X_i)$。若一个已发布姿势的所有配体重原子距所有新增重原子均不小于 8 Å，原生两体势的有限作用范围要求 $\delta_i=0$。实测全部 751 个这样的姿势–受体比较在双精度输出上严格为零。所有冻结重原子均在实际网格边界内（0.375 Å 间距，半宽 13.125 Å），这批姿势无须做越界坐标钳位。剩余 104 项的直接变化全部为负，配体内能逐项相等。

可以量化为什么这次直接改变分项仍未换首。若原赢家唯一，到下一个不同坐标的干分差距为 $g>0$，则 $g>\max_i\delta_i-\min_i\delta_i$ 足以保证赢家保持。使用该充分条件无需利用晶体标签，即可预先从分数界证明 96 个原池–补环比较中的 90 个保持，24 个并池–补环比较中的 22 个保持。未被这个粗界覆盖的情况由完整分数精确比较，结论相同。这个界与计数描述同一批固定坐标；并池产生了额外输入，不能用来申报单次盲搜的净性能。

AT9283 种子 61231 的缺段池 Oracle 为 7.383 Å。1OL7 撤约束池返回并选中 1.892 Å，此姿势放入四来源并池后，用缺段受体也会胜出。相反，danusertib 种子 60913 的缺段首姿为 7.202 Å，1OL7 撤约束首姿为 12.934 Å，在各自的发布池内交换两个受体评分仍选回各自的坐标。三种补环与缺段分别对照，24/24 次发布第一名的坐标文件指纹不同。冻结已发布坐标的反事实把此处的首位差异与上游候选变化相联系；缺段区域在真实溶液中的构象分布、重组功以及真实标准态自由能仍未测量。

## 保留所有记录的远移对照

将 1OL7 撤约束受体的 134 个新原子统一沿 x 移动 +100 Å，保持原图、顺序、类型、电荷及其他字段原样。移动后新原子距名义 26 Å 盒至少 51.793 Å，距实际外扩网格也超过 51 Å。该受体仅用于数值归因。在原二进制、两配体、四枚种子、每轨迹 25,000 名义评价上限（两轨迹）下，8/8 个完整池与缺段受体逐字节相同。记录的各轨迹计数、接受统计、起始中心及精修计数行也重现，总求值均为 402,203。新增记录的数量和插入顺序本身不足以产生这些变化。原位置上的场影响候选生成或保留的具体环节，还需要阶段轨迹才能辨认。[八份输出散列与成本](results/far.csv) · [移动前后受体定义](results/far.json) · [原始评分、全部运行日志及远移坐标](raw.tar.xz)

八次远移盲搜共耗时 2.608 秒墙钟、2.599 秒 CPU（不含制备历史受体）。定点评分的八次 C++ 调用读取已准备的坐标并写入结果，共 0.391 秒墙钟；这一数字不含 Python 拆池、距离和 RMSD 计算。独立程序用正式 CLI 对全部 1,140 条定点评分重新读入配体和坐标，并核对总分、分子间和配体内能；与三位小数输出的最大差为 0.000500。原始文件重读还核对了 855 个新增原子距离、285 个历史 RMSD 标签、160 个全精度赢家集合以及八个远移池。[独立核查](results/qa.json) · [批量评分成本](results/costs.csv)

## 复现

先按[归档说明](../REPRODUCE.md)解开输入，使 WORK 包含 base、templates 和三份补环受体。B 指向与生产核心一致、含 obj/ 和 vina 的构建目录。按自身 Boost 安装设定编译搜索路径（非系统安装可设置 CPATH、LIBRARY_PATH、LD_LIBRARY_PATH）。独立 CLI 和远移对照使用上级所列二进制；重新编译时编译器、链接依赖与构建时间会影响二进制哈希。本目录的 C++ 程序只调用正式 API，输出 17 位有效数字。

```bash
D=benchmarks/receptor_linkage/aurora/internal_loops/pool_control
OUT="$WORK/pool_control"
mkdir -p "$OUT"
c++ -std=c++17 -O2 -Isrc/lib "$D/score_pool.cpp" $(find "$B/obj" -name '*.o' ! -name main.o) \
  -lboost_thread -lboost_filesystem -lboost_serialization -lboost_program_options -lboost_system \
  -pthread -o "$OUT/score_pool"
OPENBLAS_NUM_THREADS=1 python "$D/cross_score.py" "$WORK" "$OUT/score_pool" "$OUT"
OPENBLAS_NUM_THREADS=1 python "$D/far_shift.py" "$WORK" "$B/vina" "$OUT"
OPENBLAS_NUM_THREADS=1 python "$D/check.py" "$WORK" "$OUT" "$B/vina" > "$OUT/qa.json"
for f in scores.csv pools.csv summary.csv qa.json; do cmp "$OUT/$f" "$D/results/$f"; done
```
