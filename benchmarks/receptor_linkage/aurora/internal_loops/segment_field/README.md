# 哪个补环片段改变搜索？补对配体图后，近晶体姿势还能留下吗？

在 2X6E 的 1OL7 撤约束静态模型上，只有 281–291 段能直接改变当前对接盒内的受体场。在 AT9283 种子 61231 上，加入该段曾使盲搜选中 1.892 Å 的姿势；补回配体已知环丙基边后，同预算搜索的池内最优为 7.583 Å。把旧姿势交给完整图的评分与精修，它仍是两个池中的最佳候选。这一格揭示了正确化学图下的候选覆盖缺口。其余种子和第二个配体给出了补环后恶化或基本不变的结果。[事前对照及新增种子](PROTOCOL.md) · [逐例配对差](results/pairs.csv) · [逐轨迹最早分歧](../search_replay/README.md)

## 场、坐标与化学身份

接收受体为人 Aurora A 的 2X6E。用事先归档的结合口袋共同 Cα 框架分别配准 2W1G A 链的 AT9283 和 2J50 A 链的 danusertib，对实际输出按化学等价映射计算重原子 RMSD，配体不再作刚体叠合。这里做的是跨晶体受体对接。计算沿用准备态的同一中性配体、硬蛋白框架、刚体平移/转动和声明的 5/7 个配体转轴。水、离子、蛋白运动和其他质子化态没有作为可交换自由度进入计算。两段缺失坐标来自实验模板引导的构建，真实缺段构象及溶液权重未知。[受体结构](https://www.rcsb.org/structure/2X6E) · [AT9283 结构](https://www.rcsb.org/structure/2W1G) · [danusertib 结构](https://www.rcsb.org/structure/2J50) · [制备、失败构建与配准](../README.md)

同一原子列表构成四个输入。每段或留在建模坐标，或仅将新增原子沿 x 平移 100 Å。受体历史 2,421 个原子记录逐字节相同，生产解析器复核了这些原子的 XS 类型。Vina 两体场在半径 8 Å 的格点邻域制表，再作三线性插值。26 Å 名义盒、0.375 Å 间隔实际覆盖 70³ 个胞元和 71³ 个顶点。即使试步越界，查询也会钳位到盒面，越界罚项不依赖补环原子。显式精修的距离查询同样在钳位之后进行。这些实现细节使“距整个格盒超过截断”的空间零作用可直接反驳或证实。[格点制表与插值](../../../../../src/lib/cache.cpp) · [显式查询](../../../../../src/lib/non_cache.cpp) · [Vina 搜索与经验分的原始定义](https://doi.org/10.1002/jcc.21334)

长段中 14 个重原子进入格点支持域。1.78% 是可能受影响的胞元比例，未对搜索路径或平衡构象按概率加权。将短段单独移回和将两段都远移，16/16 个完整盲搜池和全部阶段计数相同；将长段单独移回和将两段都移回，另一组 16/16 也相同。1OL5 和 1OL7 的保留约束模型中，短段至盒最近分别为 14.268 和 16.740 Å。该结论限定于这些输入、盒、钳位及短程刚性受体势。[原子级空间界](results/atom_support.csv) · [原始分型核验](results/geometry.json) · [控制实验](results/controls.csv)

AT9283 的输入距离推断少了 PDBQT 30–31 环丙基键，完整图从制备态 SDF 按原子序号映射得到。danusertib 两条路径的成键图相同，16/16 个显式/推断图对照逐字节重现同一输出及搜索计数。1,002 个输出的独立 RMSD 复核最大差 3.11×10⁻¹⁴ Å。502 个 AT9283 输出的环丙基三边介于 1.49976–1.50506 Å；500 个 danusertib 输出全部保留指定手性。两配体全部保留的重键长度相对输入 SDF 最大偏移分别为 0.001643、0.001913 Å。漏推化学边改变了内部分数及排除关系。由于环位于刚体块中，实测输出仍保持环几何。[逐化学身份与坐标复核](results/coordinate_qa.json) · [历史漏边的逐原子证明](../../PROBE.md)

## 把消失的 1.892 Å 姿势放回完整图

为解释这一预先指定病例，追加固定池与局部精修诊断。包含双远移和双段在位、推断图和完整图所产生的 573 份模式记录，均按原接收受体持坐标不动，用两张图各评分一次。对每个分子保持相同准备态和未结合能零点。1,146 项经验分数含有按转子数归一化的相互作用与内能，分子间分项在各坐标上完全相同，AT9283 的未归一化内能改变 −0.24096 至 +0.03612。32 个 AT9283 来源池仅 1 个固定池换首，16 个同种子、同受体合池亦仅 1 个换首。两个例外的几何变化分别为 12.879→12.529 和 7.700→12.712 Å。danusertib 各固定池均保留胜者。[逐姿势分项](results/fixed_graph_scores.csv) · [包括并列的逐池选择](results/fixed_graph_pools.csv)

AT9283、61231、双段在位的两池各有九个模式。完整图重搜的首姿为 8.717 Å，第三名 7.583 Å 已是全池最佳。将旧池加入后，完整图给 1.892 Å 的旧姿势 −8.834884，给新搜索首姿 −7.821322，前者领先 1.013562 个经验分。对 18 个坐标全部启动完整图的原生局优和独立 Armijo 设置（250 次名义上限），并用未结合能零点为 0 的原始 CLI 重评，均保留同一个 1.892 Å 胜者。每种设置下均仅一个起点移动超过坐标输出精度。这说明该坐标在两个实际精修入口中均能保留；点附近势面的数学驻点、盆地体积或平衡权重没有因此确定。两臂在同预算盲搜中产生不同候选池；正确图上的连续轨迹是否访问过好盆地而未保存，仍可用中间坐标进一步判别。[两种优化器全部起点](results/relax.csv) · [精修输入、输出与原始日志](relax.tar.xz)

若要从两个坐标的得分差走到相对盆地概率，需要在同一 Hamiltonian、温度及互斥盆地边界下积分，包括配体内运动、侧链和水。在同一配体、同一受体和溶液库下，游离参考和 1 M 标准体积从两盆地比值中消去；水、盐、质子化态的相对化学势只有在已指定相应库时才有定义。现有搜索没有实现这个积分，也没有新增绝对或相对标准结合自由能结果。[标准态与配分函数推导](https://doi.org/10.1016/S0006-3495(97)78756-3) · [项目物理框架](../../../../../docs/BINDING_ENSEMBLE_AND_DOCKING.md)

## 成本与复现

本轮首轮生产盲搜 112 次（含 8 次官方），共 1,002 个模式、零空池。104 次 Pro 合计 5,628,628 次有计数的梯度求值，官方二进制没有相应计数。盲搜进程的墙时之和 48.14 秒，CPU 47.83 秒；8 次官方占 12.26 秒墙时，8 次双预算 Pro 占 4.17 秒。固定池计算另用 1.68 秒墙时（8 个批次，子进程 CPU 0.29 秒）；36 次局优及其前后评分共 6.84 秒墙时、CLI 子进程 CPU 6.07 秒。试验开发时还单独跑过 18 个原生局优的先导复算，墙时 4.34 秒，再在同一套两臂程序中重跑。独立的几何分型和坐标检查分别约 0.39 秒及 1.12 秒。源结构制备和历史参照的既有开销见上级档案，未重新拟合受体、计算水或开展 MD。主机 AMD EPYC 9V74，Python 3.12.14，RDKit 2026.09.2，Gemmi 0.7.5，NumPy 2.3.5，SciPy 1.17.0。从最终脚本另行重跑 112 次，含评价的整批墙时 56.423 秒，112/112 个池的 SHA、求值数和几何统计全部复现。探针编译、开发调试、压缩和传输没有完整计时。[复核成本](results/reproduction_cost.json)

先按[上级解包说明](../REPRODUCE.md)恢复输入、实验晶体、制备态、缺段和模板结果。B 指向包含 obj/ 的 Pro 构建，OFFICIAL 指向官方 Linux Vina 1.2.7。程序支持从源码构建的 Pro；若同架构构建无法复现冻结历史池及求值数，脚本会在历史组结束后保留原始输出并标记控制失败。其他平台的浮点运算可能改变搜索路径。Boost 在非系统目录时按实际安装设置 CPATH、LIBRARY_PATH、运行时共享库目录。

```bash
D=benchmarks/receptor_linkage/aurora/internal_loops/segment_field
PC=benchmarks/receptor_linkage/aurora/internal_loops/pool_control
RUN="$WORK/segment_new"
QA="$WORK/segment_checks"
mkdir -p "$QA"
export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1
python "$D/run.py" "$WORK" "$RUN" "$B/vina" "$OFFICIAL"
python "$D/evaluate.py" "$RUN" "$QA"
c++ -std=c++17 -O2 -Isrc/lib "$PC/score_pool.cpp" $(find "$B/obj" -name '*.o' ! -name main.o) \
  -lboost_thread -lboost_filesystem -lboost_serialization -lboost_program_options -lboost_system -pthread -o "$QA/score_pool"
c++ -std=c++17 -O2 -Isrc/lib "$D/receptor_types.cpp" $(find "$B/obj" -name '*.o' ! -name main.o) \
  -lboost_thread -lboost_filesystem -lboost_serialization -lboost_program_options -lboost_system -pthread -o "$QA/receptor_types"
python "$D/score_graphs.py" "$WORK" "$RUN" "$QA/score_pool" "$QA"
python "$D/relax_union.py" "$WORK" "$RUN" "$B/vina" "$QA/local" "$QA/fixed_graph_scores.csv"
python "$D/verify_geometry.py" "$WORK" "$RUN" "$QA/receptor_types" "$QA"
python "$D/verify_outputs.py" "$WORK" "$RUN" > "$QA/coordinate_qa.json"
for f in pairs.csv controls.csv distributions.csv fixed_graph_scores.csv fixed_graph_pools.csv geometry.json atom_support.csv coordinate_qa.json; do
  cmp "$D/results/$f" "$QA/$f"
done
cmp "$D/results/relax.csv" "$QA/local/relax.csv"
```

只核验已发布的坐标和评价时，可将 raw.tar.xz 解入一个空的 RUN 目录，从 evaluate.py 开始，无需盲搜。各组的 cells.csv 记录逐次成本与输入/输出 SHA-256；modes.csv 保留全部模式、RMSD 和分数。历史官方及双预算列从上级归档原值读取。
