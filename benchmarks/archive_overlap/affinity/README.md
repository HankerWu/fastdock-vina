在三个配置的 282 个冻结首姿上，父版与本轮的十个打印能量分解逐项相同。仅 1 × 3000 的 3T1L / 28 需用扩大盒执行只读计分核对。逐分子留出影响、分骨架比较和全部 403 对的方向可从归档复算。此前相同种子与低档预算的上游及父版 188 个完整输出在本次全部逐字节重现。

## 同一搜索状态的两次回放

从出现输出变化的条件中取两个代表例。重新对接时，在实际的 save、跨轨迹 merge 和显式精修前筛选三处记录每个候选的双精度重原子坐标、能量及插入前后的成员。两次回放的每一个完整 PDBQT 均与对应无观察代码的运行逐字节相同。两种算法的候选及旧成员在首次分歧处完全一致。下表使用引擎逐原子对应距离，均以 Å 计。保存能量仅用于同一阶段的候选比较。

| 受体 / 化合物 | 首次分歧 | 新候选、原有两个邻居的能量 | 到两个邻居的距离 | 原法和本轮法的插入后占用 |
|---|---|---|---|---|
| 1KJL / 47，4 × 3000 | 第四条轨迹第九次 save | −5.2583，−5.2352，−5.0386 | 0.9736、0.9939 | 3/9 和 2/9 |
| 3T1L / 16，1 × 12000 | 第 43 次 save | −11.9727，−11.8964，−11.7532 | 0.2174、0.9786 | 9/9 和 8/9 |

1KJL/47 总计两臂均完成 83 次 save。进入跨轨迹合并的候选数从 24 减到 23，两臂都有九个进入最终显式精修。最终前七个分值相同，第八、第九的分值从 −1.904/−1.705 变为 −1.705/−1.086。首姿分均为 −3.856。

3T1L/16 在第 43 次 save 之前已经填满九个名额。空出的名额会再次触发原 MC 的“只要没满就做第二次局优”条件。整轨迹的 save 从 44 增至 59，第二次局优的联合求值从 2,783 增至 3,626，hunt 次数从 161 降至 143。两臂均有五个姿势进入显式精修。首姿经验分从 −5.904 变为 −5.736。相同总预算下，候选维护会反馈到后续搜索和计算分配。实验只给出这个配体的 Kd，没有这两个候选的实测姿势。

为检验上面的因果解释，事后在两个例子执行一次补充干预：轨迹首次装满后，移除重复候选腾出的空位不再单独触发 save，原有的能量条件仍可触发。3T1L/16 有 57 次候选保存尝试因此跳过，hunt/save 恢复至父版的 161/44，整个输出文件也与父版一致。1KJL/47 的四条轨迹该计数全部为零，完整输出与本轮默认候选维护法一致，仍有别于父版。计数版与无额外记录的研究构建在两例均逐字节一致。这两个例子参与了干预设计，提供了计算因果证据；它们不足以支持据此更换生产保存规则。[全部计数及哈希](once_full.csv) · [日志、完整坐标](once_full.tar.xz)

## 数据与复现

原始资料为 Sörme 等 Figure 4 的竞争性荧光偏振 Kd，准备后的 47 个配体、两个受体和盒子从仓库已有的归档解包。47 个配体的准备耗时在原实验中合计 105.5 秒（原实验按各准备任务耗时相加），所有臂共用同一份输入。两受体均分需要把两个受体都对接一次。母体与候选的固定坐标计分控制在每个原首姿上采用相同蛋白和配体拓扑、共用位置，检查十个打印分解值；若三位小数坐标恰好舍入至原盒外，只在两臂的 score-only 核对中将盒边长一同增加 0.75 Å。这些诊断计算没有用于搜索或选择。[测定选取、化学微态与原始实验数据](../../pair_gradient/galectin_external/README.md)

每个归档含三种核心程序的完整 PDBQT、日志、逐次时间、两种 Pro 正常 CLI 的只读工作计数及上游仪表版重放、逐格哈希、固定首姿的全部十项能量、逐对强弱和分骨架统计。上游仪表版与未插桩版在每个条件下的完整 PDBQT 逐字节一致。所有计时任务按冻结的顺序交错，单核单线程。格与格之间、两档并行工作的批次之间都不合并候选。

从仓库根目录复算所有表格（Python 3.12、NumPy、SciPy）。

```bash
D=benchmarks/archive_overlap/affinity
W=$(mktemp -d)
for layout in single four; do
  mkdir "$W/$layout"
  tar -xJf "$D/$layout.tar.xz" -C "$W/$layout"
  python "$D/replay.py" audit "$W/$layout"
done
python "$D/trace_example.py" "$D"/{1KJL-47,3T1L-16}-traces.tar.xz
```

完整重新对接需要父提交和本轮的已编译二进制；上游原版及只加计数的程序可用 [build_arms.py](../../pair_gradient/build_arms.py) 获得。以下命令中的 CPU 表示该机器上可用的一枚处理器。四轨迹组同样使用单线程。

```bash
D=benchmarks/archive_overlap/affinity
export OPENBLAS_NUM_THREADS=1
python "$D/replay.py" run "$W/new-single" --parent "$PARENT" --candidate "$CANDIDATE" \
  --upstream "$UPSTREAM" --upstream-counts "$COUNTED" --cpu 7
python "$D/replay.py" run "$W/new-four" --parent "$PARENT" --candidate "$CANDIDATE" \
  --upstream "$UPSTREAM" --upstream-counts "$COUNTED" --cpu 8 --trajectories 4
```

如要重新生成两个个案的逐步轨迹，在父版和本轮另行构建 [开发组的只读记录器](../development/instrument.py)，运行对应的原始设置，给每个进程传入唯一的 `FD_ARCHIVE_TRACE` 输出路径。

为复核四轨迹的三次计时和单轨迹统一降额，分别执行：

