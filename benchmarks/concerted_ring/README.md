# 保持闭环的协同扭转是否能找回正确姿势？

新提议能改变环形，也确实能改变一次局优进入的盆地。现有数据不足以默认启用。在独立准备的 HSP90α–3VHA，上一轮固定输入环并把搜索机会分给其余自由度，可以从化学图生成的起点找到晶体姿势。新提议损失了首轮的这项收益。新种子上两种方法各命中一次，命中的是同一枚种子。另两个独立复合物均未命中。

## 真实源码和固定状态实验

以 `fed1222` 为因果对照。它在开始时固定准备好的环内扭转，局优投影这些自由度，MC 抽中固定环时照常取角度随机数后保留原构象。`concerted_ring.h` 和 `implementation.patch` 直接替换这个空提议。局优固定在**本次传入**的环角上。因此环可以在 MC 提议间移动，而在 hunt、保存和显式精修时保持闭合。默认分支未加载研究实现。两臂的能量、梯度、局优目标、候选保留及最终评分完全相同。

设两对真实/虚拟端点的坐标差堆叠为六维向量 $g$，转角为 $q$。一根轴对所影响端点的导数等于轴方向和轴到端点向量的叉积。同一对若两端都随轴旋转，取两项之差。使用 $J=\partial g/\partial q$，对已抽到的单轴方向施加 $I-J^T(JJ^T+\lambda I)^{-1}J$；以相同原生角抽样，并用原步幅与围绕树根测量的回转半径之比限制角幅。有限步偏离流形时迭代减去 $J^T(JJ^T+\lambda I)^{-1}g$，最多六次，不能单调降低残差则恢复输入角。平方范数容差为 $10^{-12}$ Å²，阻尼 (sqrt{\epsilon}\,\mathrm{tr}(JJ^T)/6) 随尺度变化，处理两端重合约束的秩亏。只处理一个切键的双端点，在其余拓扑上沿用已有空提议。前向运动学、几何雅可比和小矩阵求解计入端到端时间。未额外计算对接能量或执行精修。此方案是搜索启发式；原 Metropolis 规则未包含反向提议密度，不能由输出解释平衡分布或游离态熵。[大环伪原子闭合](https://doi.org/10.1017/qrd.2022.18) · [协同旋转的原始工作](https://doi.org/10.1080/00268979300100641)

在三个真实 PDBQT 拓扑、三枚种子的 1152 次 MC 单步中，有 710 次抽中环。使用克隆的随机状态独立读取同一实体、同一角度。正式入口和直接调用得到完全相同的角度向量和下一随机状态，最大端点误差为 8.30×10⁻⁷ Å。与完整正运动学中央差分相比，最大雅可比误差为 5.12×10⁻⁹ Å/rad。对非环 1IEP 的正常 CLI 运行，两臂的完整坐标输出和六项工作计数相同。另用全量干净构建重跑 30 个本轮协同输出，全部逐字节一致。[冻结提议](results/frozen.csv) · [独立构建复核](results/clean_replay.csv)

## 轨迹里到底改变了什么

5T9W、7MBO、5K0X 各三枚种子、两档上限；五臂全部 0/18。以 0.1 Å 为描述性差异，空提议换成协同后，首姿在 13 格改善、4 格变差、1 格接近。这些都远离命中。一条 5K0X 轨迹在第二步首次分歧。相同输入状态，轴 1、同一抽取值 0.61559 rad，空提议与协同提议的 RMSD 仅从 14.6519 变到 14.6327 Å，hunt 结束时两者却为 14.6519 和 9.0028 Å。九个 3000 档配对的首次分歧均核对了相同的传入重原子坐标（PDBQT 精度）、随机轴和完整精度抽样值。[首次分歧](results/stages2/first_difference.csv)

147 个开发轨迹环提议全部完成校正，实际 hunt 接受 126 个。在每个真实传入状态上，空提议的直接反事实是传入构象本身。5T9W 的 40 个环提议使全配体对齐后的内部 RMSD 平均变化 +0.00009 Å，而空提议→协同的最终首姿平均从 10.323 降至 8.322 Å。5K0X 的 52 个环提议，内部 RMSD 的即时变化均值为 +0.00494 Å；最终首姿的内部误差从 1.697 到 1.695 Å，主要差异来自质心位置（9.289→5.335 Å）。7MBO 的 55 个提议也没有明显朝实验结构的方向。可以归因于机制的是允许闭环运动和搜索分叉，现有数据不能归因于更准确的环内热力学。[逐步传入、提议和 hunt 结果](results/stages2/trial_changes.csv) · [分子内误差与质心](results/panel/shape.csv)

## 冻结的独立复合物

每格为同一复合物的三枚种子乘两档上限（3000/12000），不是六个独立分子。所有臂单线程、单轨迹、相同受体和查询输入、相同 26 Å 盒、最多五个输出。盒中心来自沉积配体，只评价已知口袋。低于或等于 2 Å 视为成功。表中 Top-1、Top-5 和输出池 Oracle 三者相等；有近天然输出时均排第一。每个姿势都通过两套立体化学映射，与独立 RCSB 配体 SDF 交叉验证。每个计时臂交错跑两次，不合并候选。联合求值按 hunt、保存时局优和显式精修实际调用之和。[逐靶点成本、成功率、内存](results/summary.csv)

3VHA 是新骨架。独立 ETKDG/MMFF 制备的环本来就接近实验结构；其 RMSD 只在评价时计算。种子 458921、3000 档，固定环并重分配在 hunt 已有 0.625 Å，二次优化池最佳为 0.620 Å，保存池为 0.731 Å，最终首姿 0.752 Å。同一格空提议和协同的 hunt 池最佳仅为 18.366 和 11.025 Å。种子 458921、12000 档，空提议首姿 0.745 Å，协同却为 9.450 Å，整个输出池均缺少正确姿势。这个反例发生在发现和保留候选的链条上。3VHA 的环形相近是离线解释，输入本身怎样判断应保持这种环形，尚无可迁移判据。[逐姿势及成本](results/transfer/structures.csv) · [固定环阶段](results/held-lock-stages/models.csv) · [直接提议反事实](results/held-stages/trial_changes.csv)

登记三枚新种子并将三个受限臂的名义预算降为 9000；当前 Pro 和上游仍用 12000。3VHA 的 421831 下，原生、Pro、重分配、空提议、协同的首姿依次为 12.099、12.089、0.767、11.498、0.820 Å。其余两枚均未命中。三枚种子的 Pro / 重分配 / 协同累计联合求值为 37151 / 27858 / 27599，单次平均墙钟为 205.93 / 191.18 / 193.73 ms，CPU 时间为 205.59 / 190.87 / 193.38 ms。8H6P 和 6QBH 各臂仍全无命中。对原种子的固定 9000 协同臂，三个靶点均未命中。一次较低成本的成功支持「闭环可行且有时有用」，不足以确认自动选择环运动优于固定重分配。[新种子逐姿势](results/fresh/structures.csv) · [每次计时](results/fresh/timings.csv) · [原种子降预算](results/lower/structures.csv)

三套 CatD 的 A/B 链是同一前体成熟后的轻、重链，单链制备均缺少距配体约 2.5 Å 的蛋白原子。双链 6QBH 最近遗漏非水原子距 15.63 Å；6QBG、6QCB 仍遗漏 3.79、3.89 Å 的 DMSO，排除。PIM1/5EOL 的 CCD 生成配体和晶体配体未通过相同的立体化学比对，未运行对接。输入记录列出全部筛查对象和准备成本。所有方法共享确定性的单一预制构象。[数据来源与排除记录](results/sources.json) · [蛋白酶原始研究](https://doi.org/10.1021/acs.jmedchem.9b01351) · [3VHA](https://www.rcsb.org/structure/3VHA) · [8H6P](https://www.rcsb.org/structure/8H6P)

本次实验只更改搜索，没有修改亲和力函数。候选排名与预测结合自由能、同测定 Ki/Kd 的分子间排序是不同问题。本组独立复合物不支持推断亲和力排序提升。优先保留既有重分配作为研究比较。新方法无需新增默认开关。后续若再研究「局部状态决定固定还是转动」，应把 3VHA 划为开发数据，检验如何仅凭输入和搜索状态区分准备好的环与实际口袋不相容、还是整体落位失败。

## 复算

在有 RDKit、NumPy、SciPy、C++14 编译器及 Boost 的 Linux 环境执行下列命令。本次使用 GCC 14.2、Boost 1.83、RDKit 2025.09.3。脚本从固定 Git 修订构建五臂，另构建上游计数版本验证实际工作量和完整坐标。观察器使用每个 worker 的模型副本导出坐标，逐次核对六项工作计数和最终坐标散列。观察器、离线构象检查与重复计时均未给单次预测增加搜索机会。归档中的 inputs、logs 和坐标可脱离外部数据服务复核。制备新输入需 Meeko、PDBFixer、Gemmi、OpenMM 及其 Python 环境加入 PATH。

```bash
D=benchmarks/concerted_ring
bash "$D/replay.sh" "$(mktemp -d)"
python "$D/summarize.py" "$D/results"
(cd "$D" && sha256sum -c SHA256SUMS)
```

输入来源、运行预算和扩展登记保存在 [初始协议](PROTOCOL.md) 和 [独立验证登记](TRANSFER.md)。重做输入准备可依次运行 `prepare_transfer.py WORK 5EOL 6QBG 6QCB 6QBH 3VHA 8H6P` 和 `catd.py WORK`。另可直接解开 [独立输入](new_inputs.tar.xz)、[全部对接输出与日志](coordinates.tar.xz) 及 [阶段坐标](stage_coordinates.tar.xz)。
