# GLA 的近晶体姿势消失在哪一步

同一批 GLA 对接最终发布的 108 个姿势全部在 2 Å 之外。重放 12 次原生/CH–π 搜索，只有三个运行曾在局部优化终点产生过 ≤2 Å 的构象，三个都来自 CH–π 搜索。两个运行的近晶体构象已被蒙特卡洛链接受，却没有进入后续的二次最小化和保存；第三个运行把近晶体构象保留到显式精修结束，随后在按干分选取九个输出时落选。这里的 ≤2 Å 用于跟踪某一具体状态的失去时点，各阶段连续误差及其分布可从全量记录重算。

| 受体、种子（场搜索） | Hunt 局部优化最佳 | 已接受最佳 | 二次最小化最佳 | 轨迹最终保存最佳 | 显式精修后最佳 | 发布池最佳 |
|---|---:|---:|---:|---:|---:|---:|
| 3GXT，43103 | 1.470 | 1.470 | 2.603 | 2.612 | 2.621 | 2.621 |
| 3S5Y，43133 | 1.334 | 1.334 | 2.738 | 2.974 | 2.987 | 2.987 |
| 3S5Y，43103 | 1.252 | 1.254 | 1.277 | 1.401 | 1.353 | 2.698 |

表中是相应运行每阶段的最小 RMSD（Å）。不同列的最小值可以来自不同候选。以下归因另外核对了轨迹号、蒙特卡洛步号、坐标身份及同一精修输入的输出。其他九个运行在所有记录阶段均无 ≤2 Å 的构象；六个原生运行在 Hunt 局部优化终点的最佳 RMSD 范围为 2.189–5.998 Å，另三个场搜索为 2.595–4.010 Å。观察器没有记录每次随机突变的起点或 BFGS 线搜索内部试探位置，因而不能把最后一项结果外推为整条连续轨迹从未经过该区域。[完整十二格诊断](results/stages.csv) · [每阶段覆盖消失的位置](results/cells.csv)

**第一处损失在轨迹保存门。** 共 21,715 个 Hunt 局部优化终点，其中 103 个处于 2 Å 内。四个未被 Metropolis 接受，余下 99 个被接受。3GXT/43103 和 3S5Y/43133 分别有 8、32 个已接受近晶体状态，按相同轨迹号、步号追踪均未进入二次最小化。源代码仅在当前接受能量刷新历史最佳，或该轨迹输出尚未填满时执行这一步。这两个运行的损失能够定位到这一判断。它们不是被二次最小化从近晶体姿势推离。[按轨迹步追踪](results/lineage.csv) · [记录位置](checkpoints.patch)

**另一处损失在输出能量排序。** 3S5Y/43103 的第 3 条轨迹有 59 个近晶体接受记录进入二次最小化且仍 ≤2 Å。最终该轨迹保留其中一个坐标；其余记录与该代表的重原子 RMSD 均小于 1 Å（最大 0.951 Å），因此这 59 次出现不能视作 59 个独立盆地。该代表以 1.401 Å 进入显式精修，编号 15 的同一输入经精修后为 1.353 Å。33 个已精修候选按原生干势排序，它以 −3.511 排第 13；第九个被保留者得 −3.647。与最近输出的距离是 2.597 Å，大于 1 Å 去重阈值。重放稳定排序、容量和几何过滤可逐坐标恢复 12 个输出池的全部保留结果。这次淘汰发生在精修后的能量排序与九个名额限制之间。[精修后落选见证](results/lost_at_release.csv)

## 检查点与原始证据

每次独立运行记录四条单线程序列。Hunt 与二次最小化分别使用原流程中的截断力参数和完整搜索参数；标注为 `second` 的阶段仍使用当前搜索的网格势。随后 Late 选择将各轨迹的最终输出拼接，原生显式势分配精修名额，执行显式精修，再按原生分数和 1 Å 几何去重规则截取九个。不同阶段的能量列保留各自求值定义。

| 记录阶段 | 全部几何记录 | ≤2 Å 次数 | 出现此类记录的运行数 |
|---|---:|---:|---:|
| Hunt 局部优化终点 | 21,715 | 103 | 3 |
| Metropolis 接受后 | 18,811 | 99 | 3 |
| 二次最小化终点，进入轨迹保存器前 | 5,902 | 59 | 1 |
| 各轨迹最终保存 | 415 | 1 | 1 |
| Late 合并后 | 415 | 1 | 1 |
| 入选显式精修 | 396 | 1 | 1 |
| 显式精修及盒修正后、最终选择前 | 396 | 1 | 1 |
| 最终选择后、序列化前 | 108 | 0 | 0 |
| 实际发布 | 108 | 0 | 0 |

源码固定于 `3f21e02acabf023965d8160e8d375e1efd8edc43`，先应用原有 CH–π 研究补丁，再应用三个翻译单元的只读检查点。观察器复用历史归档的序列号映射和输出流，不调用随机数或能量/梯度求值。所有正式输出文件逐字节匹配冻结池，每次运行的轨迹/接受/初始质心/显式精修记录 14 行也逐字匹配。启用记录后约 31 MiB 输出，12 次对接子进程的墙钟/CPU 为 3.778/3.744 秒；原四臂对应为 3.279/3.268 秒。这些单次计时包含写轨迹的代价，不用于推断算法加速。[运行计时、完整检查点流与姿势的 SHA-256](results/replay.csv)

[原始轨迹、日志与实际输出](raw.tar.xz) 保存 17 位有效数字的坐标及各阶段的能量。每条记录含阶段、轨迹编号（合并后为 0）、步号或阶段内序号、能量，随后按对应的 `atoms` 行给出重原子坐标。图映射来自同一质子化 DGJ input，晶体对照与口袋变换见[原结构实验](../README.md)。[逐记录 RMSD 与阶段分数](results/events.csv.xz) 有 48,158 行阶段观察，另有 108 个最终发布坐标供比对。[各阶段最接近晶体的原始坐标](results/best_coordinates.json.xz) 保留化学图重排后的原子顺序。独立读取完整压缩包并按 PDBQT 序号向量化计算所有 RMSD，最大数值差 3.56×10⁻¹⁵ Å，全部阈值判断一致。未向搜索器提供晶体姿势或 RMSD。[全量核验](results/coordinate_check.json)

## 离线复算

在仓库根目录执行。前四步直接分析已提交的完整原始记录。重新运行二进制需要 C++14、Boost 和项目原有 Python 环境，Python 依赖与 GLA 四臂相同。自定义 Boost 可在构建命令末尾增加 `--boost-prefix /path/to/boost`。

```sh
D=benchmarks/ch_pi_search/gla_transfer
W=$(mktemp -d)
mkdir "$W/work" "$W/raw" "$W/frozen"
tar xf "$D/inputs.tar.xz" -C "$W/work"
tar xf "$D/trace/raw.tar.xz" -C "$W/raw"
python "$D/trace/analyze.py" "$W/work" "$W/raw" "$W/recalculated"
python "$D/trace/verify_coordinates.py" "$W/work" "$D/trace/results" "$D/trace/raw.tar.xz"
tar xf "$D/outputs.tar.xz" -C "$W/frozen"
sh "$D/trace/build.sh" "$W/build"
python "$D/trace/replay.py" "$W/work" "$W/frozen" "$W/build/vina" "$W/replayed"
python "$D/trace/analyze.py" "$W/work" "$W/replayed" "$W/from_replay"
diff "$W/recalculated/stages.csv" "$W/from_replay/stages.csv"
```
